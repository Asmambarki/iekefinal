Ajoute à mon site une gestion sécurisée des utilisateurs et des rôles pour permettre aux personnes qui travaillent avec moi d’accéder à l’administration. Conserve toutes les fonctionnalités existantes : Supabase, gestion des produits, gestion des stocks, promotions, commandes et tableau de bord. Je veux deux rôles principaux : admin employee 1. Rôle administrateur Le rôle admin correspond au propriétaire de la boutique. L’administrateur doit avoir accès à toutes les fonctionnalités : tableau de bord complet ; chiffre d’affaires ; coûts des produits ; bénéfices ; marges ; panier moyen ; statistiques financières ; export des données financières ; gestion des commandes ; gestion des produits ; gestion du stock ; gestion des promotions ; gestion des photos ; gestion des catégories ; gestion des utilisateurs et des employés ; création, modification et désactivation des comptes employés. 2. Rôle employé Le rôle employee doit pouvoir utiliser toutes les fonctionnalités nécessaires au travail quotidien, sauf les informations financières sensibles. L’employé peut : consulter la liste des commandes ; ouvrir le détail d’une commande ; consulter les coordonnées du client ; appeler le client depuis le numéro affiché ; modifier le statut d’une commande ; confirmer une commande ; rejeter une commande ; annuler une commande ; mettre une commande en préparation ; marquer une commande comme expédiée ; marquer une commande comme livrée ; ajouter des notes administratives ; consulter les produits commandés ; imprimer les détails d’une commande ; rechercher et filtrer les commandes ; ajouter un produit ; modifier un produit ; supprimer ou masquer un produit ; modifier le nom et la description d’un produit ; modifier le prix initial et le prix de vente ; ajouter ou modifier une promotion ; ajouter, remplacer ou supprimer les photos ; modifier les catégories ; consulter et modifier le stock ; augmenter ou diminuer le stock ; consulter les alertes de stock faible ; consulter les produits en rupture de stock. 3. Informations interdites aux employés Un employé ne doit jamais pouvoir consulter : le prix d’achat ou cost_price ; le coût total d’une commande ; le bénéfice d’une commande ; le bénéfice par produit ; le chiffre d’affaires global ; les marges ; le panier moyen financier ; les graphiques de revenus ; les graphiques de bénéfices ; les statistiques financières ; la valeur financière du stock ; les exports contenant les coûts ou les bénéfices ; les paramètres sensibles de Supabase ; les clés API ; la gestion des comptes administrateurs ; la création ou la suppression d’autres administrateurs. Les employés peuvent voir le prix public et le prix de vente des produits, car ces prix sont nécessaires pour gérer la boutique et les commandes. 4. Table des profils utilisateurs Crée une table Supabase nommée user_profiles avec les champs suivants : id : identifiant correspondant à l’utilisateur Supabase Auth ; full_name : nom complet ; email : adresse email ; role : admin ou employee ; active : compte actif ou désactivé ; phone : téléphone facultatif ; created_at ; updated_at; last_login_at. Le champ role doit accepter uniquement : admin employee Un utilisateur dont active est égal à false ne doit plus pouvoir accéder à l’administration. 5. Authentification Utilise Supabase Auth pour la connexion. Conserve une seule page de connexion : /admin/login Après la connexion : récupère le profil de l’utilisateur ; vérifie son rôle ; vérifie que son compte est actif ; redirige l’utilisateur vers l’interface adaptée à son rôle. Si le compte est désactivé, déconnecte immédiatement l’utilisateur et affiche : Votre compte a été désactivé. Contactez l’administrateur. Ne crée aucune inscription publique. Les comptes doivent être créés uniquement par l’administrateur. 6. Gestion des employés Ajoute une page réservée aux administrateurs : /admin/users Cette page doit permettre de : voir la liste des employés ; rechercher un employé ; ajouter un employé ; saisir son nom complet ; saisir son adresse email ; définir son rôle ; activer ou désactiver son compte ; modifier ses informations ; réinitialiser ou renvoyer une invitation ; consulter sa dernière connexion. Avant de désactiver un compte, demande une confirmation. Un administrateur ne doit pas pouvoir supprimer ou désactiver accidentellement son propre compte. Un employé ne doit jamais voir cette page. 7. Menu selon le rôle Adapte automatiquement le menu de l’administration. Tableau de bord employé Crée un tableau de bord opérationnel sans informations financières. L’employé peut voir : nombre de nouvelles commandes ; commandes à confirmer ; commandes en préparation ; commandes à expédier ; commandes livrées ; commandes rejetées ; produits en rupture ; produits avec stock faible ; nombre total de produits actifs ; dernières commandes reçues. Ne montre aucun montant global, bénéfice, coût ou chiffre d’affaires. Dans les listes de commandes, l’employé peut voir le total payé par le client, mais pas le coût ni le bénéfice. 9. Protection des informations financières Ne te contente pas de masquer les informations dans l’interface. Protège réellement les données avec Supabase Row Level Security et des fonctions sécurisées. Un employé ne doit pas pouvoir récupérer les champs financiers en : modifiant l’adresse de la page ; appelant directement l’API Supabase ; inspectant les requêtes réseau ; modifiant le code dans le navigateur ; utilisant une requête personnalisée. Les champs suivants doivent être accessibles uniquement aux administrateurs : cost_price cost_total line_cost gross_profit line_profit toutes les statistiques de revenus, coûts, marges et bénéfices. Crée des vues ou fonctions Supabase séparées pour les employés afin de ne retourner que les colonnes autorisées. Par exemple : une vue sécurisée pour les commandes des employés ; une vue sécurisée pour les articles des commandes ; une vue sécurisée pour les produits sans cost_price ; des fonctions financières accessibles uniquement aux administrateurs. 10. Permissions sur les commandes L’administrateur et l’employé peuvent modifier les statuts des commandes. Conserve toutes les règles existantes : confirmation de commande ; préparation ; expédition ; livraison ; rejet ; annulation ; restauration du stock en cas d’annulation ou de rejet ; prévention des doubles restaurations de stock. Enregistre pour chaque changement : l’identifiant de l’utilisateur ; son nom ; son rôle ; l’ancien statut ; le nouveau statut ; la date et l’heure ; la note éventuelle. 11. Historique des actions Crée une table activity_logs contenant : id user_id user_name user_role action entity_type entity_id description old_values new_values created_at Enregistre notamment : création d’un produit ; modification d’un produit ; suppression ou masquage d’un produit ; modification d’un prix ; modification d’une promotion ; modification du stock ; changement du statut d’une commande ; rejet ou annulation d’une commande ; création ou désactivation d’un employé. Seul l’administrateur peut consulter l’historique complet. L’employé peut uniquement voir ses propres actions récentes dans la page Mon profil. 12. Sécurité des comptes Ajoute : déconnexion automatique lorsque la session expire ; bouton de déconnexion ; protection de toutes les routes administratives ; vérification du rôle à chaque accès ; message d’accès refusé ; redirection vers la page correcte ; possibilité pour l’utilisateur de modifier son propre mot de passe ; impossibilité pour un employé de modifier son propre rôle. Ne place jamais de clé service_role dans le navigateur. Les opérations de création de comptes et de modification des rôles doivent être effectuées côté serveur avec une fonction sécurisée. 13. Interface Affiche en haut de l’administration : le nom de l’utilisateur connecté ; son rôle ; son avatar ou ses initiales ; un bouton Mon profil ; un bouton Se déconnecter. Utilise les libellés suivants : Administrateur Employé L’interface doit fonctionner sur ordinateur, tablette et téléphone. 14. Tests obligatoires Effectue les tests suivants. Test administrateur L’administrateur doit pouvoir : voir le chiffre d’affaires ; voir les coûts ; voir les bénéfices ; gérer les produits ; gérer les commandes ; gérer les employés. Test employé L’employé doit pouvoir : consulter et gérer les commandes ; modifier les statuts ; gérer les produits ; gérer les promotions ; gérer les photos ; gérer le stock. L’employé ne doit pas pouvoir : voir le prix d’achat ; voir le bénéfice ; voir le chiffre d’affaires global ; ouvrir une page financière ; accéder à /admin/users ; modifier son rôle ; récupérer les informations financières directement depuis Supabase. Test de compte désactivé Lorsqu’un administrateur désactive un employé : sa session doit être refusée ; il doit être déconnecté ; il ne doit plus pouvoir accéder aux données administratives. Conserve le style visuel actuel du site et ajoute cette gestion des rôles sans casser les fonctionnalités existantes.
